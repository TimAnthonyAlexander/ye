# Ye — project notes

## Repo layout

`src/` and `scripts/` are the product. Three other tracked trees are not: `docs/` (nine reference docs — OVERVIEW, PIPELINE, PROVIDERS, PERMISSIONS, SUBAGENTS, TOOLS, SKILLS, STORAGE, REASONING_STORING), `img/` (screenshots the README links), and `web/` — a Vite + React 19 + MUI landing site with its own `package.json`, `bun.lock` and `tsconfig.json`. `web/` is a second, entirely separate dependency tree; nothing in `src/` imports from it and `bun run check` does not cover it.

`.ye/` is checked in: the repo dogfoods its own loaders. `.ye/skills/release/SKILL.md` is the authoritative release procedure (bump version → commit → push → `bun run release`).

There is no `.github/`. No CI runs anywhere — `bun run check` is a local gate and nothing enforces it.

## Conventions

- TypeScript on Bun, `tsc --noEmit` for typechecking (`bun run typecheck`). No emit — Bun runs `.ts` / `.tsx` directly.
- Module system: ESNext, `verbatimModuleSyntax`, `.ts` extensions in all imports (Bun resolution). `allowImportingTsExtensions: true`.
- JSX: `react-jsx` (Ink 5).
- Formatting: Prettier — 4-space indent, 100 print width, double quotes, trailing commas `all`, LF (`.prettierrc.json`). `.prettierignore` excludes `*.md`, so this file is not formatted by the gate. No other linter configured.
- Strictest tsconfig flags: `strict`, `noUncheckedIndexedAccess`, `noUnusedLocals`, `noUnusedParameters`, `noImplicitOverride`, `noFallthroughCasesInSwitch`.
- Run cycle: `bun run dev` for watch-mode, `bun run start` for single run. `bun run build` compiles to `dist/ye`.
- Comments: zero by default. Add one only for non-obvious WHY (hidden constraint, invariant, workaround). Never for WHAT — identifiers carry that.
- No defensive programming against internal state — validate at system boundaries only (user input, external APIs, config load). Internal code is trusted.
- `readonly` on all interface/type fields that aren't mutated after construction.
- Async generators for streaming pipeline hooks (`queryLoop`, `runTurn`). Events flow as `AsyncGenerator<Event>`.
- No `any`. Explicit error types for provider-specific failures: `MissingApiKeyError`, `MissingAnthropicKeyError`, `MissingOpenAIKeyError`, `MissingDeepSeekKeyError`, all covered by `isMissingKeyError()`. Ollama does not throw a missing-key error — local server, no auth by default.
- Never write a literal control character into a source file. Use an escape (`\0`, `\r\n`, `\x1b`) — a raw byte makes the file binary to git and diffs become useless. `src/sourceHygiene.test.ts` enforces this: it walks `src/**` plus root-level `.ts/.tsx/.md/.json` and fails on any byte below 9, between 14 and 31, or 127. Markdown is deliberately in scope — this file was once committed as a binary blob.

## Build & test

- `bun install` — dependencies. Three runtime deps: `ink` (^5.1.0), `react` (^18.3.1), `turndown` (^7.2.0). The LSP client is hand-rolled precisely to avoid a fourth.
- `bun run typecheck` — `tsc --noEmit`.
- `bun test` — Bun's test runner against the in-tree `*.test.ts` files.
- `bun run check` — typecheck + format check + tests, the pre-commit gate.
- `bun run build` — `scripts/install.sh`: detects the host target (macOS arm64/x64, Linux x64/arm64), calls `scripts/build.ts`, outputs `dist/ye`, symlinks onto `$PATH`.
- `scripts/build.ts` is the real compile entrypoint for both install and release. It calls `Bun.build({ compile })` with a plugin that stubs `react-devtools-core` and `--define`s `process.env.DEV="false"`. Never swap it for a bare `bun build --compile` or `--external` — the file's own header records the startup crash that produced this arrangement.
- `bun run release [vX.Y.Z]` — `scripts/release.sh` cross-compiles `ye-macos` (bun-darwin-arm64), `ye-linux` (bun-linux-x64), `ye-windows.exe` (bun-windows-x64) through the same `build.ts`, then publishes via `gh release create --generate-notes`. Tag defaults to `v` + `package.json` version.
- `scripts/` also holds nine tracked one-off debug scripts (`debug-openrouter.ts`, `debug-reasoning*.ts`, `debug-ddg.ts`, `find-free-models.ts`). Not part of any build.
- `ripgrep` is optional. Grep spawns `rg` and falls back to a pure-Bun scanner (`src/tools/grep/fallback.ts`) when the binary is missing, synthesising rg's exit semantics. The install script warns if `rg` is absent but nothing breaks without it.
- Known test hazard: several suites `mock.module` process-globally, which leaks across the in-process isolate. `src/pipeline/executeToolCalls.test.ts` mocks both `../tools/index.ts` and `../hooks/index.ts`; `backgroundWakeup.test.ts`, `tools/task/index.test.ts`, `tools/taskOutput/index.test.ts` and `subagents/background.test.ts` do the same. Three other suites carry explicit workaround comments for it. A test that passes alone but fails in the full suite is almost always colliding with the tools barrel mock.

## Architecture

Entry: `src/cli.tsx`. Flag parsing lives in `src/cli/flags.ts` (separate module so it is testable — `cli.tsx` runs `main()` at import). Flags: `-p/--prompt`, `--mode`, `--model`, `--provider`, `--resume [id]`, `--continue`, `--output-format text|json|stream-json`, `--max-budget-usd`, `--update`/`--upgrade`, `-h/--help`, `-v/--version`. `--resume` and `--continue` together error. An unrecognised **flag** errors and exits 1; a bare positional is silently dropped, so `ye "fix the bug"` opens the TUI with the prompt discarded. With no `-p` and a non-TTY stdin the prompt is read from stdin (`echo "fix it" | ye`), trimmed, capped at 10MB; empty stdin aborts. `--mode` applies interactively only — `runHeadless` hardcodes AUTO and never receives it.

Headless bypasses Ink and streams via `pipeline/headless.ts`; `src/cli/output.ts` holds the machine-readable serialisers. `stream-json` emits a deliberate allowlist of seven event types (`turn.start`, `turn.end`, `model.text`, `tool.start`, `tool.end`, `shaper.applied`, `recovery.retry`) — the two prompt events are excluded because they carry `respond` callbacks. `abort()` in `cli.tsx` guarantees a well-formed `RunSummary` on stdout for `json`/`stream-json` even when the run never reaches the pipeline (bad config, unreadable stdin, unresolvable resume).

`src/cli/write.ts` writes to fds 1/2 with `writeSync`, an EAGAIN retry loop and an EPIPE swallow. Async `process.stdout.write` plus `process.exit` truncated piped `--help` at the 512-byte pipe boundary. `src/cli/stdin.ts` reads `Bun.stdin.stream()` rather than `process.stdin` because `patch-stdin.ts` monkey-patches `process.stdin.read()`.

`--model` and `--provider` (`src/cli/overrides.ts`) rewrite the in-memory config for one run and are never handed to `saveConfig`. A provider given without a model carries that provider's registry default, the rule `/provider` follows — the configured model id usually belongs to the provider being replaced. The provider id is validated in `parseFlags` against `PROVIDER_IDS`; a model id is not, because model lists are dynamic and the provider is the authority.

"Never persisted" needs one guard: the boot key prompt calls `saveConfig` with the whole in-memory config, so an overridden run where the user types a key would have written the override to disk permanently. `cli.tsx` hands `<App>` the on-disk identity (`persistedModelOf`, captured before the override) and every config write that is not the user explicitly picking a model goes through App's `persistConfig`, which restores it via `withPersistedModel`. `/model` and `/provider` still persist — that is the user choosing, not a flag.

`--continue` resolves to a concrete transcript in `src/cli/resume.ts` before anything opens, so a missing session errors instead of silently starting fresh; it never opens the picker. Bare `--resume` interactively opens the picker, and `--resume <id>` interactively is the one case that resolves **after** the TUI mounts — `app.tsx` calls `loadSession` in a try/catch and renders `resume failed: …` in place. Headlessly both pre-resolve. `runHeadless` replays the JSONL into the starting history, restores `sessionRules` and `maxGlobalTurnIndex`, re-opens the same file in append mode, and reports that session id in the `RunSummary`.

UI layer: `src/components/`. Home screen + recents picker, chat, input, status bar, todo panel, permission/key/user prompts, edit diff renderer, thinking spinner (`thinking.tsx`) and the live reasoning tail (`thinkingBlock.tsx` — 5 lines × 100 cols while streaming, collapsed after).

The file index is loaded at boot from `loadFileIndex()` and **re-scanned every time the mention picker opens** behind a 1500ms TTL, so files created mid-session appear without a restart.

Typing while the model streams queues the message rather than dropping it: it renders under the input, ↑ on an empty buffer pops the last queued message back for editing, and Ctrl+C with something queued aborts the turn and immediately drains the queued message instead of posting `(stopped)`. Hidden prompts (markdown commands, skills) queue the same way.

Context shaping and provider recovery are visible, not just machine-readable: `shaper.applied` and `recovery.retry` render as dim system lines (`✻ microcompact · freed ~12k tokens`, `↻ overloaded · retry 2/3`, `↻ fell back to anthropic/claude-x`). The formatting and the coalescing live in `src/components/notices.ts` as pure functions so they are testable without Ink. A stalled provider can retry ten times in one turn, so the first retry of a kind gets a line and the kind is then flushed at `turn.end` as one `retried N times` — `N` is the total for that kind, including the one already printed, and a kind that only retried once is not flushed at all. A model fallback is never folded into a count — which model answered is a fact about the reply.

Ctrl+O is one verbose toggle, not two: it expands Read/Glob/Grep groups **and** switches the tool-result rendering. Collapsed, a successful result renders nothing and an error renders clipped at 200 chars; verbose renders the full result capped at 100 lines / 4000 chars, marked `… N more lines` or `… truncated` when the char cap bites mid-line (`src/components/toolResult.ts`). Because `<Static>` never re-renders what it already emitted, flipping it repaints the same way a terminal resize does — clear, reset `committedCount`, bump `chatKey` — so scrollback honours the new setting instead of freezing at the old one.

Pipeline: `src/pipeline/`

- `queryLoop` drives turns; `runTurn` is one full turn.
- Assemble: system prompt + notes hierarchy + auto-memory → `Message[]`. Full prompt ~17k tokens; Ollama and small models get a compact variant (~4k) via `buildSmallSystemPrompt()`. `assemble` short-circuits entirely on `state.systemPromptOverride`, so a subagent gets neither the notes hierarchy nor auto-memory.
- `gitStatus.ts` injects `git status --porcelain` as a `<system-reminder>` user message before assembly on **every** turn, 30-line cap. The output is hashed, so an unchanged tree costs one line (`git status unchanged since last turn`) instead of the full listing; a clean tree gets its own one-liner.
- `routing.ts` resolves per-turn provider options. Precedence: explicit `providerOrder` → `providerSort` (legacy advanced override) → `routing` strategy → `cheapest`. Strategies are `cheapest | fastest | latency | sticky`. `sticky` pins to `state.pinnedUpstream[model]`, captured by `capturePinnedUpstream` from the first usage event's upstream field, and falls back to `price` until a pin exists. `/model` and `/provider` clear the pins.
- Shapers: cheapest→most-expensive chain `budgetReduction → snip → microcompact → contextCollapse → autoCompact`. Each returns `skip`/`applied`/`done`; history is re-assembled after each `applied`. Hard cap of 4 applications per turn. `clampBudget` re-runs as a finalizer after any shaper applied, so a shrunk prompt recovers reply budget up to `initialMaxTokens`. `PreCompact` hook can block the chain. `/compact [focus]` drives the same summariser on demand via `shapers/manualCompact.ts`.
- Model call: `dispatch.ts` streams provider events under a 180s inter-chunk inactivity timeout (300s total for non-streaming); a stall aborts that attempt on a derived signal and surfaces as a retryable `stream_error`, which is what triggers the streaming→batch switch. `recovery.ts` wraps with retry + backoff, that fallback, forced shaper escalation on `prompt_too_long`, `max_tokens_invalid` → halve-and-retry, and a `fallbackModel` last resort. Rate limits get a **separate** budget: 10 retries at 1s→60s, against the general 3 at 500ms→8s. No retry fires once any text or tool call has streamed.
- Permission gate + tool execution: read-only tools whose gate decision is `allow` fan out in parallel; everything else runs sequentially. AskUserQuestion is excluded from the fan-out despite being read-only — its result raises an interactive prompt.
- Stop check: `evaluateStop()` in `stop.ts`. Reasons: `end_turn`, `max_turns`, `plan_loop_guard`, `budget_exhausted`, `user_cancel`, `error`, `continue`. (`context_overflow` is still in the union but nothing emits it — overflow is handled inside `recovery.ts` as `prompt_too_long`.)
- Plan acceptance: approving `ExitPlanMode` sets `state.planJustAccepted`, and the next turn opens by injecting `PLAN_APPROVED_REMINDER` **before** the model call. Without it the model reads back only the bare `{"kind":"request_mode_flip",…}` tool result — which records that a prompt was *requested*, never that the user answered it — and asks "shall I start?" after the user already said yes. `PLAN_START_REMINDER` stays as the after-the-fact backstop: a plan approved last turn followed by a text-only turn converts `end_turn` → `continue`, once. The flag was declared and read but never assigned until 3.7.2, so that backstop had never once fired.
- Ghost-wait (`ghostWait.ts`): if the model says "waiting for/on/until" with nothing actually running — no background shells, subagents or monitors, and no background call started this turn — a nudge is pushed and the chain continues. `queryLoop` then buffers the whole next turn's events; if that turn is a trivial text-only ack, the reply is popped and the nudge dropped so the user never sees the exchange. The buffer is released the moment a tool call appears, because holding past it deadlocks on `permission.prompt`'s callback. Fires at most once per user prompt, never in PLAN mode. The regex requires an object ("waiting for the tests") so the noun sense doesn't fire.
- Verify loop (`verify.ts`): when the chain would end and something was written, runs `verify.typecheck → lint → test`, stopping at the first failure. A failure is injected as a `<system-reminder>` and the chain continues so the model fixes it; success injects nothing. Capped at 2 continuations. Main chain only — `state.parentSessionId` marks a subagent run, and without that gate every subagent ending its chain would fire the whole suite.
- Budget: `--max-budget-usd` / `config.budget.maxUsd`, checked before dispatch so nothing is spent past the cap.
- Headless has a `MAX_HEADLESS_WAKEUPS = 50` backstop on the background-pump loop.

Providers: `src/providers/` — `openrouter` (default), `anthropic`, `openai`, `deepseek`, `ollama`, `dario`.

- `openrouter` — SSE, OpenAI-compatible tool calls, context window from `/models`, routing as above, server-side web search/fetch, per-model reasoning policy in `reasoningPolicy.ts`. `cacheControl.ts` adds **two** explicit breakpoints — last system message and tail — gated on `model.startsWith("anthropic/")`, since only Anthropic routes need them.
- `anthropic` — native tool-use blocks, **three** `cache_control` breakpoints (system, last message block, last tool), server-side web search forwarded as a builtin tool.
- `openai` — Responses API, `store:false`, strict tool schemas, encrypted reasoning round-trip, `prompt_cache_key` set from the project id. `prompt_cache_retention: "24h"` is gated on `/^gpt-5\.[1-9]/` — gpt-5.0/4.1/codex-mini 400 on the param, gpt-5.5+ require it.
- `deepseek` — implicit prefix caching, native reasoning round-trip.
- `ollama` — local, keyless, NDJSON streaming, context size from `/api/show`.
- `dario` — "Anthropic (Subscription)". Claude on a Pro/Max subscription through [dario](https://github.com/askalf/dario), an unofficial local proxy at `http://localhost:3456` that speaks the standard Messages API and re-auths each request with the subscriber's OAuth token. Not a new protocol: `providers/dario/index.ts` is a thin builder over `createAnthropicProvider`, which is parametrized on `id` / `contextSizes` / `capabilities` and otherwise shares `adapt.ts` and `stream.ts` verbatim. Keyless like Ollama (placeholder key `dario`, `DARIO_API_KEY` when the proxy sets one), `serverSideWebSearch: false` so WebSearch falls through to Brave/DuckDuckGo, and absent from `pricing.ts` on purpose — a flat-fee plan has no per-token dollars, so `/cost` and `/usage` record null rather than inventing zero. Model ids are dario's namespace, where a trailing `[1m]` is a **client-side label** the proxy strips in favour of the `context-1m` beta: plain ids are 200K, `[1m]` ids are 1M.
- `errors.ts` owns the `ProviderErrorKind` taxonomy and the retryable set. Body-sniffing there is what turns a 400 into `prompt_too_long` (the trigger for forced shaper escalation), and `classifyMidStreamError` is what recovers overloaded/rate-limit out of a 200 stream.
- `tryBuildProvider()` in `build.ts` handles key prompts and config persistence. Per-call USD in `pricing.ts`. `resolveApiKey` / `setProviderApiKey` live in `apiKey.ts`, not `build.ts`: `build.ts` imports the registry, so a provider module importing it back closes a cycle that only evaluates cleanly when the registry happens to load first. Every provider imports `apiKey.ts`.
- `/model` draws from three sources, not one: the static registry (`models.ts`), the OpenRouter free-model cache (`openrouter/freeModels.ts`), and Ollama's `/api/tags`. `freeModels.ts` pulls `/models`, filters to $0 prompt+completion / text modality / ≥32k context, then **probe-tests each candidate for real tool calling** — strict `tool_choice` first, falling back to `auto` when the upstream rejects it — and writes a version-stamped cache loaded at import. `/model refresh` drives it.
- `internalCall.ts` routes calls the user never reads — compaction summaries, session titles, auto-memory selection, WebFetch summaries, prompt suggestions — to `config.cheapModel` with reasoning disabled. Precedence: `webTools.summarizeModel` (WebFetch only) → `cheapModel` → active model. Note the first branch keeps the *active* provider options, so reasoning is **not** disabled there. The cheap model may live on another provider, built through the same path `recovery.ts` uses for `fallbackModel`. If it cannot be built the call falls back to the active model — a missing cheap model must never break compaction. Session titles are the exception: with no `cheapModel`, `storage/title.ts` uses a hardcoded per-provider pick (openrouter → `~google/gemini-flash-latest`, anthropic and dario → `claude-haiku-4-5`) and returns `null` for openai, generating no title rather than spending the active model on one.

dario setup: `src/dario/`. dario is a daemon the user also drives from their own shell, so selecting the provider walks the whole path rather than printing instructions. `ensureDarioReady` (`setup.ts`) runs inside `switchProvider` before `tryBuildProvider` — binary missing → consent picker → `npm install -g @askalf/dario` (bun only when npm is absent, because `dario upgrade` itself shells out to npm) verified by `dario --version`; proxy down → consent → detached `dario proxy` polled to readiness; `/health` 503 → consent → `dario login --no-proxy` with the terminal handed over the same way Ctrl+G hands it to `$EDITOR`. Three yeses at worst, none of them implicit. The install lands in the global npm prefix, **not** `~/.ye` — a `~/.ye`-private copy would not be on `PATH` for the `dario login` the user may run themselves — and the consent text says so, along with the plain fact that dario is third-party and that only Anthropic can rule on account risk. Only a declined install aborts the switch; everything past it is advisory, matching how Ollama treats a dead daemon. 503 detail is read out of `/health`'s `oauth` + `expiresIn`, which is where dario puts the operator-facing reason.

Four consequences of that flow worth knowing before debugging it:

- **dario replaces Ye's tools with Claude Code's unless the request is shaped like a CC one.** Its default ("template") path rewrites the whole request: `system` becomes `[billing tag, CC agent identity, CC's own ~25KB system prompt + Ye's appended]`, and `tools` becomes Claude Code's canonical definitions filtered to the CC-native names Ye happened to declare. Ye's schemas are discarded, and every tool CC does not have — Task, TodoWrite, BashOutput, KillShell, KillAgent, KillMonitor, Diagnostics, SaveMemory, the three LSP tools — is round-robined onto a CC fallback slot and never advertised at all. The model is then Claude Code: it reads CC's prompt, sees CC's schemas, and answers `Read(file_path)`, `AskUserQuestion(questions: [...])`, `EnterPlanMode()`, and invents `TodoWrite`/`Task` calls out of the prompt text — which is where `todos` once arrived as a JSON *string* rather than an array, four calls in a row. The escape is dario's passthrough path: `isGenuineCCClient()` forwards `system` and `tools` byte-faithfully, keeping only dario's billing tag at `system[0]`, its identity headers and its cache breakpoints. The discriminator is purely structural, so `providers/dario/passthrough.ts` puts two marker system blocks in front of Ye's own — block 0 carrying `x-anthropic-billing-header:`, block 1 naming the Claude Agent SDK — and blanks the `user-agent` Bun would otherwise send, since that header is forwarded verbatim on this path and `Bun/1.3.1` is not what a CC request looks like. `anthropic/adapt.ts` emits one system block per system message for the same reason. Measured against dario 5.5.32 with the same eight-tool surface: without the markers, `Read{file_path}` plus a `Write` to a fabricated `~/.claude/projects/.../memory/` path; with them, `Read{path}` and `SaveMemory{title,hook,content}`. Both requests classified `five_hour` at `GET /analytics` — the wire shape stays on subscription billing.

- **dario deletes `<system-reminder>` blocks, so Ye renames them.** Its `ORCHESTRATION_TAG_NAMES` list scrubs `system-reminder`, `env`, `thinking`, `task_metadata` and ten others from every outbound request; of those Ye only ever emits `system-reminder`, and it emits it constantly — git status, background bash / subagent / monitor notices, lazily-loaded subdirectory notes, verify failures, the plan and ghost-wait nudges. Through dario none of it reached the model. Worse, a message that was *only* a reminder scrubbed to an empty text block still carrying Ye's cache breakpoint, and dario's prefill guard restored it by reference (its `tailContentBeforeScrub` aliases blocks it mutated in place), so Anthropic answered `messages.N.content.0.text: cache_control cannot be set for empty text blocks` — a non-retryable 400 that killed the turn. That is exactly the shape every continued-after-a-text-only-turn nudge produces. `providers/dario/reminders.ts` rewrites the tag to `<system-note>` before the shared adapter builds the body; dario's own `--preserve-orchestration-tags` opt-out is set on the daemon at startup, so Ye cannot rely on it when the user runs their own proxy.

- **The login step usually never fires.** dario resolves credentials `~/.dario/credentials.json` → `~/.claude/.credentials.json` → OS keychain (macOS service `Claude Code-credentials`), so on any machine with Claude Code installed `dario login` detects rather than authenticates and no browser opens. `DARIO_IGNORE_CC_CREDENTIALS=1` narrows it to dario's own file. A first switch that goes straight from install to a working Opus turn is the expected path, not a sign that something was skipped.
- **Subscription billing is verifiable, and not from Ye.** Anthropic classifies every response with `anthropic-ratelimit-unified-representative-claim`; dario reads it and aggregates at `GET /analytics` (`dario usage`). `five_hour` / `seven_day` and their `_fallback` and `_overage_included` variants are subscription; `api` and `overage` are not. dario's overage guard halts the proxy with a 503 on the first `overage` response until `dario resume` or a 30-minute cooldown, so paid drift stops traffic rather than accruing. Ye deliberately reports none of this itself — inventing a billing verdict from the client side is exactly the kind of claim that goes stale.

`sonnet-5` / `fable-5` reached Ye through this work, which also widened `rejectsSampling()` (`anthropic/models.ts`, formerly `isOpusWithNoTemp`): sampling params are a 400 from Opus 4.7 onward and across the whole 5 family, while the 4.6 line still accepts them. Opus 4.8 is deliberately the **first** registry entry for `anthropic`, `openrouter` and `dario` alike, so `defaultModelFor` keeps picking it over Opus 5 on a provider switch.

Tools: 25 registered in `src/tools/registry.ts` — Read, Edit, Write, Bash, BashOutput, Grep, Glob, Definition, References, SymbolSearch, Diagnostics, TodoWrite, ExitPlanMode, EnterPlanMode, AskUserQuestion, Task, TaskOutput, KillAgent, Monitor, KillMonitor, WebFetch, WebSearch, Skill, SaveMemory, KillShell. The three LSP navigation tools leave `listTools()` when no language server is configured, so that drops to 22.

`src/tools/pool.ts` filters further before the model sees anything, and this is where the real numbers come from: ExitPlanMode is removed outside PLAN (it is PLAN-only), so the steady-state pool is **24 with LSP, 21 without**. PLAN narrows to its 11-name allowlist (8 without LSP). Headless drops AskUserQuestion and EnterPlanMode. `webSearchAvailable === false` drops WebSearch. Blanket-deny rules pre-filter too.

Read-only (auto-allow in NORMAL), 13 tools: Read, Glob, Grep, Definition, References, SymbolSearch, Diagnostics, AskUserQuestion, Skill, WebFetch, WebSearch, BashOutput, TaskOutput. The PLAN allowlist (`src/permissions/modes.ts`) is **not** a subset of that set — it excludes Diagnostics (which runs an arbitrary user-configured command) along with BashOutput and TaskOutput, and adds ExitPlanMode, which is not read-only.

`normalizePathArg` (`src/tools/paths.ts`) rewrites a relative or `~` `path` arg to absolute for Read/Edit/Write/Glob/Grep, and it runs in `turn.ts` **before** the permission gate. That ordering is the whole point: gate and tool must resolve the same file, or a deny rule gets evaluated against a different path than the one written. It is also why those five tools accept relative paths at all.

`applyArgAliases` (`src/tools/argAliases.ts`) runs immediately before it, in the same `turn.ts` line and for the same reason. Claude models call tools with **Claude Code's** parameter names whatever schema they are handed: Opus 4.8 called Read with `file_path` four times in one turn, through an error message that named `path`. The table folds `file_path` → `path` (Read/Edit/Write), `subagent_type` → `kind` (Task), `skill` → `command` (Skill), `-i` → `case_insensitive` (Grep) and `shell_id`/`task_id` → `bash_id` (BashOutput/KillShell). Ours wins when both keys are present, and a tool whose names already agree — Bash, Glob, WebFetch, WebSearch, TaskOutput, KillAgent — is deliberately absent from the table. A key Claude Code has that we do not (`description` on Bash, `-n` and `head_limit` on Grep) is dropped by `validateArgs`, which ignores unknown keys. That silent drop is only safe where ignoring the key cannot change the answer, which is why Grep grew `case_insensitive` and `multiline`: a dropped `-i` returns case-sensitive hits to a model that asked for case-insensitive ones, and reports no error. The fallback scanner is line-based, so it refuses `multiline` outright rather than reporting no matches.

Two divergences a key rename cannot reach are handled where the value is, not in the table. Claude Code's `Task` types are `general-purpose` / `Explore` against our `general` / `explore`: `resolveKind` (`subagents/catalogue.ts`) resolves a kind that differs only in case, separators or CC's spelling, and only when the name given is not itself a catalogue entry — so a markdown agent literally named `general-purpose` still wins, which is what "mapping the values could run a different agent" was the fear of. Claude Code's `AskUserQuestion` takes `questions` (an array) against our one `question` plus `options`: the tool now accepts both, and `executeToolCalls` puts a multi-question call to the user one question at a time, joining the answers as `question: answer` lines. Nothing is dropped, so nothing has to fail.

`EnterPlanMode`'s `reason` is optional for the same reason: Claude Code's takes no parameters at all, so a Claude model calls ours with `{}`, and the reason is worth asking for and not worth failing a turn over. `ExitPlanMode` still requires `plan` — there is no way to invent a plan the model did not send — so its description says outright that the plan text is passed, not read from a file.

`validateArgs` repairs the rest. An `array` or `object` argument that arrives as a **string** holding JSON is parsed (a whole session's TodoWrite calls once arrived that way, four in a row, each rejected as `arg todos must be array`); a numeric or `"true"`/`"false"` string is coerced to the declared scalar; an enum value differing only in case or separators resolves to the real one. What it cannot repair it explains: errors now name the type that arrived and append a schema-derived example of the call — `arg todos must be array (got string). Expected {"todos":[{"content":"string","status":"pending|in_progress|completed"}]}`.

`TodoWrite` used to be a third: Claude Code's items are `{content, status, activeForm}` against our `{id, content, status}`, and `validateArgs` waved them through because it never descended into `items`, so every todo carried `id: undefined`. The validator now checks item schemas, and `id` is gone — it was read in exactly one place, as a React key, and the panel keys by index instead. `activeForm` is dropped like any other unknown key.

Edit always requires a prior Read this session and rejects on a content-hash mismatch. Write requires one only when the file already exists, and a successful Write counts as a Read for later edits in the same turn. Both checkpoint the file before writing — that is what `/rewind` restores.

Edit/Write run the configured formatter after a successful write (`src/tools/format.ts`, gated on `format.enabled`, 10s timeout enforced by a process-group hard kill). A formatter failure never fails the edit — the file is already written, and reporting failure makes the model retry and duplicate work — but it does surface as a one-line `note` on the tool result, so the model is told. The recorded content hash is refreshed after a formatter rewrites a file, otherwise the next Edit is wrongly rejected as drifted, and Edit renders its diff preview from the post-format content so a reflowing formatter cannot hand back stale line numbers.

Output caps: Bash 32,000 chars, Grep 32,000, LSP tools 32,000 and 500 entries.

Async work: `Task` runs in the background by default, `Bash` on `run_in_background: true`, and `Monitor` polls a condition. Managers in `src/subagents/background.ts` and `src/tools/bash/background.ts` hold results until a turn drains them into history as `<system-reminder>`s. `pipeline/backgroundWakeup.ts` races all three round-robin from a moving cursor, so a kind that always has a result waiting cannot starve the others; both the Ink loop and headless pump turns off it. The three have different backstops: background Bash defaults to the 900s ceiling (against the 120s foreground default), background subagents to a 20-minute **inactivity** watchdog swept every 30s, monitors to their own give-up deadline plus a 60s per-poll timeout.

Subagents: `src/subagents/`. Four built-in kinds plus user-defined ones:

- `explore` — codebase search (Read/Glob/Grep + the LSP navigation tools). `thoroughness` sets the budget (5/15/25 turns).
- `general` — Read, Edit, Write, Bash, Grep, Glob, TodoWrite. Seven tools, AUTO mode. Not the full toolset: no WebFetch, WebSearch, Skill, Diagnostics or LSP.
- `verification` — post-change verification (Read/Glob/Grep/Bash/Diagnostics).
- `fork` — same tool set as `general`. Inherits a deep copy of the parent's live in-memory history plus a message stating that it is a fork and what its task is. Model-facing only; there is no slash command. The copy shares no object with the parent so the fork's shapers cannot write back, and the seed is trimmed at a clean tool-call boundary so no orphaned tool call reaches the provider. `parentHistory` rides on `SubagentToolContext` — seeding from a transcript replay would miss the current turn.
- Custom agents from `<projectRoot>/.ye/agents/*.md`, `~/.ye/agents/*.md`, and — read **unconditionally** — Claude Code's `<projectRoot>/.claude/agents/*.md` and `~/.claude/agents/*.md` (`src/subagents/custom/load.ts`, `catalogue.ts`): `name`, `description`, `tools`, `model`, `maxTurns`. For the `.ye` dirs the `name` must equal the filename or the file is silently dropped; the `.claude` dirs follow Claude Code and identify the agent by frontmatter `name` alone (filename need not match, `nameFromFrontmatter`), and are walked recursively. An empty body drops it either way. Precedence low→high: claude-user → user → claude-project → project, so a `.ye` file beats a `.claude` file of the same name and project beats user. Declared tools are intersected with the built-in ceiling — the 11-tool union of explore + general + verification — and `Task` is always excluded. Omitting `tools` grants that whole ceiling, which is *wider* than any single built-in kind, so "a file can only narrow" is true only relative to the ceiling. `maxTurns` stays clamped by `config.maxTurns.subagent`. Built-ins beat project, project beats user. The `Task` kind enum is built from the live catalogue.

None of them can spawn a `Task` — recursion guard.

Background subagents are steerable, not just observable. ↓ opens the agent list (`src/components/subagentTabBar.tsx`) whenever background tasks exist — the input buffer is not checked, so it fires mid-draft and with a picker open. The list is **vertical, one row per agent**, `main` first, and selecting a row *is* opening it: the selected agent's live transcript (`src/components/subagentTranscript.tsx`) renders above the list with the same `RenderItem`/`ToolCallView` the main chat uses, and `main` is the row that shows the ordinary chat. So ↑↓ move between agents from anywhere in the panel, in the direction the list is drawn, and ↑ off the top row closes the panel and hands the keys back to the prompt. There is no browse/open split and no Esc — Esc reads as "stop this agent", which it never did.

The transcript does not scroll. It follows the newest output (`windowFromBottom` at offset 0) and says `… N earlier off screen` when it cannot fit everything, so the arrows are free for navigation. `moveSelection` in the tab list is a pure function precisely so this is testable without Ink (`subagentNav.test.ts`).

Two things that look redundant and are not. `<Chat>` stays mounted behind the transcript with no items — `<Static>`'s internal cursor is what stops committed scrollback re-emitting, so unmounting it would duplicate the whole conversation on the way back. But blanking its props cannot *unprint* what `<Static>` already wrote to the terminal's own scrollback, so entering a transcript also clears the screen and leaving it repaints with the same `\x1b[2J\x1b[3J\x1b[H` + `setCommittedCount(0)` + `bumpChatKey()` the resize handler and Ctrl+O use. Without that clear the main conversation stayed on screen and the transcript drew underneath it.

The stop confirm lives in App, not in the tab list: the steer composer is live at the same time, and a bare `y` would answer the confirm *and* land in the draft. For the same reason the kill is **Ctrl+K**, not a bare `k` — plain letters belong to the composer now.

Typing in the transcript appends to that agent's mailbox (`src/subagents/mailbox.ts`). `queryLoop` drains it at the **top** of a turn, never mid-turn — a message is only "delivered" once a turn reads it, and only that position guarantees one follows, so a steer can never splice between an assistant tool call and its result. A steer landing as the chain ends revives it for another turn, but `maxTurns.subagent` still wins: at the ceiling the message is rejected with the reason rather than silently stretching the budget. The mailbox closes the moment the task leaves `running` (one `settle()` covers all five terminal transitions), so a message typed at a finished agent is refused out loud. Queued, delivered and rejected messages are all visible — queued below the transcript, delivered inline as user turns, rejected in red. Steering is UI-only by design: the pipeline gets `MailboxDrain`, which can take messages out and refuse them but never put them in. Ctrl+K stops the selected agent through the same `manager.kill()` path `KillAgent` uses, behind a confirm where `y` accepts and **any other key** cancels.

Permissions: `src/permissions/`. Two filters run in `tools/pool.ts` before anything is asked — the PLAN mode allowlist and blanket-deny rules remove tools from the pool entirely. Then `decide()` evaluates: pattern denies → pattern allows → mode default → heuristic gate as a safety floor that can only tighten. That floor only ever fires for **Bash** — `extractBashCommand` returns `null` for every other tool, so a risky non-Bash call is never elevated.

`match.ts` holds the pattern language: an explicit per-tool subject map (Bash → `command`, Read/Edit/Write/Glob/Grep → `path`, WebFetch → `url`, …), with anything outside the map falling back to the first string-valued arg as `text`. Path subjects are matched against absolute tilde-expanded paths, globbed when the pattern contains glob characters and compared as an exact string when it doesn't; Glob/Grep substitute `process.cwd()` when `path` is absent. An allow rule fires only when **every** chained segment matches, so `Bash(git status)` does not permit `git status && rm -rf /`; a deny fires when **any** segment matches. Allow also refuses segments containing command substitution unless the rule names it. Patterns ending in `:*` keep v1 `startsWith` semantics for backward compatibility.

Prompt responses are `allow_once`, `allow_session`, `allow_always`, `deny`.

- `allow_session` records a **blanket, pattern-less** rule for the whole tool, written to the session JSONL and restored on replay (gated on `permissions.persistSessionRules`, default on), tagged with the prompt ordinal so a rewind past a grant discards it.
- `allow_always` **writes a derived rule to `~/.ye/config.json` permanently** — that is the point of the response — and downgrades the current call to `allow_once` so the session never gains a grant wider than the rule shown. It derives the narrowest rule it can (`npm run build` → `Bash(npm *)`, an edit → `Edit(<dir>/**)`), shows the exact text before the user accepts, and refuses to derive from chained commands, command substitution, wrappers that can run anything, risky commands, a path containing a wildcard, a text arg that is empty or over 200 chars or contains `*?()\n`, or any directory with fewer than two path segments (which covers `$HOME` and `/usr` alike).

Hooks: `src/hooks/`. Seven events — `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `PreCompact`, `SessionStart`. **Exit code 2 blocks only on the three awaited events**: `PreToolUse`, `UserPromptSubmit`, `PreCompact`. The other four are fired as `void runEventHooks(...)` and their exit codes are discarded. `SubagentStop` never fires for a failed subagent — the isolate throws on `errorMessage` first. Headless fires only `SessionStart` and `UserPromptSubmit`.

The hook contract: JSON payload on stdin, `YE_EVENT` / `YE_TOOL_NAME` / `YE_FILE_PATHS` / `YE_PROJECT_DIR` in the environment, 60s default per-hook timeout, output capped at 32k, and a timeout or abort degrading to `continue`.

Skills: `src/skills/`. Agent-Skills-compatible loader. Six tiers, later overriding earlier by name: **builtin → managed → claude (`~/.claude/skills`) → user (`~/.ye/skills`) → claude-project (`<proj>/.claude/skills`) → project (`<proj>/.ye/skills`)**. Two skills are embedded in the binary (`frontend-design`, `project-init`). Both `.claude` tiers are read **unconditionally** (no flag — most users came from Claude Code) and identify a skill by its **directory name**, matching Claude Code, so the frontmatter `name` there is only a display label and need not match the directory (`nameFromDirectory` in `parse.ts`). The old `skills.enableClaudeInterop` config key is gone. Honoured frontmatter: `name`, `description`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `argument-hint`. Tool scoping **intersects** — a skill can never hand back a tool the mode stripped. Scope also pins a model for the rest of the chain, is last-skill-wins (a skill declaring nothing clears the previous narrowing), lives per-session in `skills/scope.ts`, and is cleared when the chain ends. Unknown keys are ignored; malformed values skip the key, not the skill.

LSP: `src/lsp/` + `src/tools/lspTools/`. Hand-rolled stdio client — byte-level frame buffering so a response split mid-header or mid-body reassembles, one lazily spawned server per `(root, configKey)` reused across calls, 10s request timeouts, in-flight requests rejected when a server dies. Scoped to navigation only; `Diagnostics` owns compiler output. Line/column are 1-based in the tool API, converted at exactly one place (`lspTools/shared.ts`). Tests drive a fake server (`src/lsp/fixtures/fakeServer.ts`) speaking real framed JSON-RPC with its own parser.

SymbolSearch is the one tool that warms up first: a cold tsserver answers `workspace/symbol` with an empty list rather than an error, so it opens a same-server file and polls up to 5s for a symbol resolving in a *different* file before trusting an empty result.

LSP install: `src/lsp/install/`. A language server is useless if the user has to install it themselves, so Ye offers. `catalogue.ts` holds one entry per language (typescript, python, go, rust) with its binary, markers, prerequisite and install plan; `config/detect.ts` derives its detection table from the same catalogue, so adding a language is one edit.

Servers install under `~/.ye/lsp` — node servers into a private package root, `gopls` into `bin/` via `GOBIN`. `rm -rf ~/.ye/lsp` is a complete uninstall. `rust-analyzer` is the exception: it goes through `rustup component add`, mutates a toolchain Ye does not own, is tagged `toolchain` scope, and uninstall prints the command rather than running it. That scope tag also controls resolution — `resolveServerBinary` falls back to `$PATH` **only** for `toolchain` entries, which is why rust-analyzer reports `source: "path"` while a system-wide `gopls` does not count as Ye-installed.

One builder feeds both the string shown to the user and the argv spawned, so consent cannot be given for one command and another run. Installs are verified afterwards by resolving and probing the binary — a package manager exiting 0 without producing a working server is a failure. No `sudo`, ever.

`offer.ts` is the policy layer. `pendingOffers()` returns nothing when the session is non-interactive, `lsp.autoInstall` is false, `lsp.enabled` is false, `autoDetect` is false, the project has no marker, a server already resolves (including a catalogue alternate like `pylsp`), the language was declined, or the prerequisite is missing. Only declines persist, to `~/.ye/lsp/state.json` — "installed" is derived by resolving the binary and so cannot go stale. A corrupt state file reads as no declines rather than failing the session.

The offer surfaces once at session start as a non-modal banner (Ctrl+L to answer); ignoring it and typing is not consent. `/lsp` shows status and drives install/uninstall explicitly, and `/doctor` explains why LSP is off. Ye-installed binaries resolve before `$PATH` and are spawned by absolute path — a modified `PATH` is inherited by children but not by anything they re-exec. After an install `invalidateLspAvailability()` makes the navigation tools appear on the next turn with no restart.

Monitors: `src/monitors/`. Ye can be woken by work it started, but nothing let it wait on state it does not own — a job finishing on a remote host, a CI run going green, a log line appearing, a wall-clock time arriving. A background bash `until` loop cannot do it either: `resolveTimeoutMs` hard-clamps to `MAX_TIMEOUT_MS` (900s) and real waits are hours.

A monitor polls a cheap shell `condition` on an interval (default 30s, floor 5s) and completes when it succeeds, then runs `capture` once for the payload. `condition` answers *whether*, `capture` fetches *what* — keeping the condition quiet (`grep -q`) is what makes frequent polling cheap while still waking with evidence. Each spawn gets 60s; the default give-up is 24h. `at` accepts an ISO timestamp or `HH:MM`; with a condition the two combine as OR, whichever fires first.

The error taxonomy is load-bearing: exit 0 is met, exit 1 is not yet, anything else — a non-{0,1} exit, a spawn failure, a poll timeout — is an error, and errors must be **consecutive** to matter (one flake between not-yets resets the counter). Three in a row stop the monitor as `broken` with the last stderr. A monitor spinning silently for a day because an SSH key expired is the failure this design exists to prevent. Outcomes are `condition_met`, `time_reached`, `gave_up`, `broken`, `killed`. `gave_up` means the condition was never observed true, and is never reported as a fact about the underlying work.

Monitors are a third `BackgroundKind` and drain into history as `<system-reminder>`s exactly like background bash and subagents. They live only as long as the session, are torn down at `/clear` and unmount and in the headless `finally`, and in a `-p` run the deadline is clamped to an hour so a headless run cannot hang. `/monitors` lists them, `KillMonitor` and `/monitors kill` stop one.

Storage: all under `~/.ye/`. `src/storage/paths.ts` defines the layout. Sessions are append-only JSONL. Project ID is a stable 12-char hex hash of the absolute project root. Cross-session prompt history in `~/.ye/history.jsonl`, per-call usage in `~/.ye/usage.jsonl`, turn checkpoints under `<projectDir>/checkpoints/<sessionId>/<turnIndex>/` powering `/rewind`, and plans written by `ExitPlanMode` under `<projectDir>/plans/<adjective>-<noun>.md`. Subagent sidechains go to `<projectDir>/sessions/<parentSessionId>/sidechains/` — a directory beside the parent's `<parentSessionId>.jsonl`, not inside it.

Session titles are generated through `internalCall` and also drive the terminal title bar (`writeTerminalTitle` / `resetTerminalTitle`, reset on clear and exit).

Memory: `src/memory/`. Hierarchy: `/etc/ye/CLAUDE.md` → `~/.ye/CLAUDE.md` → project → `YE.local.md` (gitignored). At the project level it is **first found wins** across `CLAUDE.md` → `YE.md` → `AGENTS.md`, never concatenated — a repo with both `CLAUDE.md` and `AGENTS.md` reads `CLAUDE.md` only. Symlinked notes files resolve correctly (this repo's `CLAUDE.md` is a symlink to `YE.md`).

A line that is exactly `@<path>` inlines that file, resolved relative to the importing file, with `~` expansion, capped at 4 hops, cycle-safe, and skipped inside fenced code blocks. The spec must look like a path — it needs a `/` or a `.md` suffix — so a bare `@todo` on its own line stays literal. A missing target stays literal rather than failing the session.

`CLAUDE.md`/`AGENTS.md` in subdirectories load lazily: reading a file appends any notes between it and the project root as a `<system-reminder>`, once per session. Root-level files are excluded so the lazy path cannot undo first-found-wins.

Auto-memory: LLM-based selection, no embeddings, no vector DB. It reads exactly two **index** files — `~/.ye/MEMORY.md` and `~/.ye/projects/<hash>/memory/MEMORY.md` — each a list of `- [Title](path) — hook` lines, with link targets resolved relative to the index's own directory (absolute allowed, so an entry can point anywhere). No directory is ever globbed. The model is shown only `title — hook` lines, never file bodies, and picks at most 5; only the chosen files are then read whole. That is what makes the selection call cheap. `SaveMemory` writes project scope only — `<projectMemoryDir>/<slug>.md` plus the index line — and has no path to the global index. (`GLOBAL_MEMORY_DIR` is exported from `paths.ts` with zero readers; dead.)

`@mention` expansion (`src/mentions/expand.ts`) is more than a picker: it appends a `<mentioned-files>` block to the prompt with file contents up to 1000 lines, folders as an 80-entry listing, 256KB total budget, and anything outside the project root or non-existent silently skipped. Untruncated mentioned files count toward the read-before-edit invariant, so `@file.ts` followed by an Edit works without a Read.

Slash commands: `src/commands/`. 26 built-ins: `/help /clear /context /compact /copy /cost /usage /diff /status /btw /export /memory /permissions /agents /monitors /doctor /lsp /config /mode /provider /model /routing /resume /rewind /init /exit`. Two aliases, `/new` → `/clear` and `/quit` → `/exit`, reserved against markdown and skill commands as well.

`/config` is a settings list: one line per setting, ↑↓ to move, ←→ to change the value on the current line, Enter to type an exact number or string, Esc to save, Ctrl+C to discard. The editable surface is pure data in `src/config/registry.ts` — dotted path, label, kind, range, default, description — and everything else (rendering, navigation, persistence) reads from it, so the whole thing is testable without Ink. Each line is tagged `(configured)`, `(detected)` or `(default)`, or `(pending)` while an edit is uncommitted. `/doctor` and `/status` only ever emit the first two — `Origin` has no third value.

The `/config` edit path never round-trips the validated `Config`: `validate.ts` drops top-level keys it does not model, and serialising it back would silently delete anything the user hand-wrote. `src/config/edit.ts` re-reads the raw JSON, sets only the dotted paths that changed, and writes via temp file + rename. A key equal to its default is not written unless it was already there, so the file does not bloat with restated defaults; a delete prunes the block it emptied. `ensureInvariants()` fills the five keys `validate.ts` demands of a block that exists (`compact.threshold`, `maxTurns.master`, `maxTurns.subagent`, `permissions.defaultMode`, `permissions.rules`) — writing one optional leaf into a block the file did not have would otherwise produce a config that fails to load. Blocks a one-line widget would misrepresent — `providers`, `hooks`, `permissions.rules`, `format.formatters`, `lsp.servers`, `webTools.allowedDomains`, `webTools.blockedDomains`, the model pairs — render as read-only summary rows so the editor never claims to be the whole surface.

Note the caveat: `saveConfig` still serialises the whole validated `Config` and is used by `/model`, `/provider`, `/routing` and the boot key prompt. Those paths *can* drop hand-written unknown keys. Only the `/config` editor is safe.

`/cost` is this session broken out per call kind (`turn`, `summarize`, `title`, `memory`, `webSearch`, `webFetch`) plus a total, followed by a bare lifetime total; `/usage` is the lifetime log split by provider and by model over three windows (24h, 7d, all time), from the same `~/.ye/usage.jsonl`. `/diff` renders `git diff HEAD` for the project root in the same red/green/`… N unchanged lines` language as the inline Edit diffs, capped so a large diff cannot flood the scrollback, and lists untracked files (`git ls-files --others --exclude-standard`, capped at 10). `/context` reports percentages relative to the **compaction trigger** (`contextWindow × compact.threshold`), not the raw window, using the shapers' identical `chars/4` estimator on purpose — so it can never say "OK" while a shaper is firing. At the default threshold of 0.5 that halves every number a reader would otherwise expect. `/help` lists commands **and** keybindings — the home-screen tip promises both.

User-defined markdown commands load from `<projectRoot>/.ye/commands/` and `~/.ye/commands/`, recursively, with subdirectories namespaced by `:` (`git/sync.md` → `/git:sync`). Frontmatter `description` and `argument-hint`; the body is sent as a hidden prompt with `$ARGUMENTS` and `$0..$N` substitution. Precedence: **built-in > project markdown > user markdown > skill**.

`/btw` asks a side question that touches neither `state.history` nor the session JSONL, so resume cannot replay it.

## Config reference (`~/.ye/config.json`)

All optional unless noted. Validated in `src/config/validate.ts`; unknown top-level keys are dropped.

- `defaultProvider`, `providers.<id>.{baseUrl, apiKeyEnv, apiKey?}`, `defaultModel.{provider, model, providerOrder?, allowFallbacks?, providerSort?, routing?}` — required core. `routing` is `cheapest | fastest | latency | sticky` (default `cheapest`, OpenRouter only, ignored when `providerOrder` is set); `providerSort` is the legacy advanced override that beats it.
- `compact` — `threshold`, `defaultMaxTokens`, `minReplyTokens`, plus per-shaper tuning: `snipThreshold`, `snipFloor`, `snipProtectedTail`, `snipMaxPerTurn`, `microcompactThreshold`, `microcompactHotTail`, `microcompactMinBytes`, `collapseThreshold`, `collapsePreserveRecent`.
- `maxTurns.{master, subagent}` — the subagent value is a ceiling nothing else can raise.
- `permissions.{defaultMode, rules[], heuristicGating?, persistSessionRules?}` — `persistSessionRules` writes grants to the **session JSONL**, not to the config (the type comment in `config/types.ts` says otherwise and is stale).
- `verify.{enabled?, lint?, test?, typecheck?, timeoutMs?}` — drives both the post-edit verify loop and the `Diagnostics` tool.
- `format.{enabled?, formatters?}` — `formatters` maps an extension glob to a command template; `$FILE` is substituted with the quoted path, or appended when absent. Detected entries use broad multi-extension globs, not single-extension ones.
- `budget.maxUsd` — session spend cap.
- `cheapModel.{provider, model}` — root-level; serves internal calls.
- `suggestions.enabled` — predicted next prompt.
- `lsp.{enabled?, servers?, autoInstall?}` — `servers` maps a language id (`"typescript"`) to `{command, args?}`. `autoInstall: false` suppresses install offers; it never causes an install, which always needs an explicit answer.
- `gitStatus.{enabled?, maxLines?}` — default on, 30 lines.
- `webTools`, `recovery`, `hooks` — as before.
- `autoDetect` — root-level boolean, default true. Kill switch for the runtime detection below.

## Auto-detection (`src/config/detect.ts`)

`verify`, `format` and `lsp` need values (which command, which server), not flags, so a fresh config leaves all three dark. They are detected from the project root at runtime instead. **Nothing is ever written back to `~/.ye/config.json`** — a persisted detection goes stale and then lies about the project.

Detection is keyed on the project root the caller passes and cached in a module-level Map. `verify`/`format` cost one `readdirSync` plus at most one `package.json` parse per root per process; `lsp` additionally does `statSync` + `accessSync` over two directories per candidate binary and falls through to `Bun.which` for every catalogue language whose marker is present. A root with none of the markers detects nothing, which is why tests that pass a temp directory are unaffected.

| Block | Detected from (first match wins) |
| --- | --- |
| `verify.typecheck` | `scripts.typecheck` → `<pm> run typecheck`; `tsconfig.json` → `<pm-exec> tsc --noEmit`; `Cargo.toml` → `cargo check`; `go.mod` → `go build ./...` |
| `verify.lint` | `scripts.lint` → `<pm> run lint`; `.eslintrc*` / `eslint.config.*` → `<pm-exec> eslint .`; `biome.json(c)` → `<pm-exec> biome check .` |
| `verify.test` | **never detected** |
| `format.formatters` | `.prettierrc*` / `prettier.config.*` / a `prettier` key in `package.json` → prettier; else `biome.json(c)` → `biome format --write $FILE`; plus `go.mod` → `gofmt -w $FILE` |
| `lsp.servers` | binary resolvable **and** the language marker present: `typescript-language-server` + tsconfig/package.json, `gopls` + `go.mod`, `rust-analyzer` + `Cargo.toml`, `pyright-langserver` (else `pylsp`) + `pyproject.toml`/`requirements.txt` |

"Resolvable" for LSP means `~/.ye/lsp/bin` and `~/.ye/lsp/node/node_modules/.bin` first, then `$PATH` — Ye-installed servers win. The language list is hand-written prose over a table the code derives from `lsp/install/catalogue.ts`, so it will rot silently when a fifth language is added.

The package manager comes from the lockfile (`bun.lock`, `bun.lockb`, `pnpm-lock.yaml`, `yarn.lock`, `package-lock.json`), defaulting to bun. Binaries run through the project's own `node_modules/.bin` (`bunx`, `pnpm exec`, `yarn exec`, `npx`) — a bare `tsc` or `prettier` is rarely on `$PATH` even as a devDependency.

Precedence, in order:

1. `autoDetect: false` disables all detection; explicit config still applies.
2. `enabled: false` on a block is an absolute veto — that block detects nothing.
3. Explicit config wins **per field**, not per block: setting only `verify.lint` still gets a detected `verify.typecheck`. `lsp.servers` merges per language key; `format.formatters`, being one map, is replaced wholesale when set.
4. `enabled` resolves true when set true, or when unset and at least one command/formatter/server resolved.

`test` is never detected on purpose: a suite is slow, and one pre-existing failure would trap the model in the verify loop for two extra turns on every chain, forever. It runs only when the user names the command.

`/doctor` and `/status` print the effective values, each tagged `(configured)` or `(detected)`; `/doctor` also says when `autoDetect` is off. `src/lsp/availability.ts` is the odd caller — `listTools()` has no context, so it reads the raw config file and resolves the project root itself (`resolveProjectRoot()`), once per process.

## Notes

- `performance-findings.txt` at root is a temporary analysis doc — not part of the build.
- Default model is `~google/gemini-flash-latest` via OpenRouter. Default `compact.threshold` is 0.5.
- Subagents run in-process (no sandboxing) and return a single summary string to the parent.
- Self-update: `ye --update`. A background check on launch (24h TTL cache at `~/.ye/update-check.json`) surfaces in the status bar. It refuses to update when the executable basename is `bun` — that means running from source. Windows uses a `.old` rename dance plus `cleanupWindowsOldBinary()` on every launch. `EACCES`/`EPERM` suggests `sudo ye --update`.
- Ctrl+C cancels reverse-search, then clears input, then aborts the stream — never exits. Use `/exit` to quit.
- Key bindings: Shift+Tab cycles mode, Ctrl+O toggles verbose output, Ctrl+G composes the buffer in `$VISUAL`/`$EDITOR` (falling back to `vi`, or `notepad` on win32; a non-zero editor exit discards the edit), Ctrl+R searches cross-session prompt history, Ctrl+L answers the LSP install banner, Shift+Enter inserts a newline (Alt/Option+Enter fallback), Ctrl+W deletes the word before the cursor, ↓ opens the background agent list (↑↓ then move between agents, ↑ off the top closes it, Ctrl+K stops the selected one).
- Input prefixes and pickers: `!cmd` runs a one-off shell command, `@` opens the file-mention picker, `/` opens the command picker, `:` opens the emoji picker (`src/emoji/`, 4 rows, ↑↓ pick, Enter or Tab insert, Esc cancel — the colon must start the token, follow whitespace, or follow an emoji, so `abc:jo` and `http://x:y` don't trigger). All pickers: ↑↓ move, Enter accepts, Tab completes into the buffer, Esc dismisses.
- Readline editing in the input: Ctrl+A/E move to the start/end of the **logical** line (delimited by `\n`, not a wrapped visual row), Ctrl+K/U kill to the end/start of it, Ctrl+Y yanks the last kill, plus Ctrl/Meta+Backspace/Delete word delete and Ctrl/Alt+arrow word navigation. One kill slot, last kill wins; an empty kill leaves it alone. Home/End are Ctrl+A/Ctrl+E — Ink's `Key` has no flag for either and blanks their `input`, so `patch-stdin.ts` rewrites both sequences (`src/ui/keySequences.ts`) before Ink sees them. That rewrite is why `permissionPrompt` ignores every Ctrl/Meta chord: Ink reports one as the bare letter, and Home would otherwise answer `a` = allow_always.
- Prompt suggestions (`suggestions.enabled`, `src/suggest/`): after a clean chain, one predicted next prompt is generated on the cheap model (batch, not streamed) with reasoning forced off even on the active-model fallback, capped at 24 tokens and then hard-truncated to **72 chars** at a word boundary with no ellipsis — the binding limit, and deliberate, because an accepted suggestion becomes editable buffer text. Shown as dim ghost text in an empty idle input. Tab or Right accepts it into the buffer without submitting; any keystroke, Esc, or a paste dismisses it. Tab precedence is mention accept → slash-picker accept → emoji accept → command completion → suggestion accept, so it can never shadow a picker. Generation is fire-and-forget and returns `null` on any error — a failed suggestion must never surface an error.
- `patch-stdin.ts` rewrites Kitty/modifyOtherKeys sequences for Ink. Its terminal write is guarded by `isTTY` — unguarded, it prefixed piped `--help`/`--version`/`-p` output with a raw escape.
